# 定制规则：可改与不可改（resume-tailor 参考）

## 不可改（改了就拒绝写入）

| 字段 | 原因 |
| --- | --- |
| `experiences[].company` | 公司名是背调第一项，写错等于造假 |
| `experiences[].period` | 在职时间决定年限，写法可以统一格式，但不能变 |
| `experiences[].position` | 职级同理（「高级前端工程师」不能写成「前端负责人」） |
| `educations[].school` / `.degree` / `.period` | 学历是最容易核验的部分 |
| 条目**数量** | 新增一条经历/项目/学历就是编造 |

服务端会校验前四项与条目数，违反直接拒绝并说明原因（`validateTailor`）。

## 可改（鼓励改）

| 动作 | 说明 | 例子 |
| --- | --- | --- |
| 重排项目 | 与 JD 技术栈重合多的排前面 | JD 要数据可视化 → ECharts 项目提到第一位 |
| 重排技能 | 按 `plan.reorderSkills` 顺序 | React / TypeScript 前置，Less 后置 |
| 重述职责 | 同一事实换 JD 的说法 | 「维护 BFF 层」→「用 Node.js 维护 BFF 层，承接 3 个前端业务的接口聚合」 |
| 突出口径 | 把结果写具体，但数字必须真实 | 「优化了性能」→「首屏从 3.2s 降到 1.4s」（用户提供过才写） |
| 压缩无关内容 | 与这个 JD 无关的经历可以缩到一行 | 校招时期的社团经历 |
| 统一术语 | JD 写 `Node.js` 就别写 `nodejs` | 让关键词能被搜索到 |

## 摘要（selfIntroduction）怎么写

1. 一句话身份 + 年限：`6 年前端，主攻增长与性能。`
2. 一句话最强证据：`做过日活千万级产品的性能治理，首屏从 3.2s 到 1.4s。`
3. 一句话为什么是这家：`你们这块是增长链路 + 数据看板，正好是我做过的两件事。`

字数控制在 120 字内。招聘方只看前两行。

## 重述的安全边界

判断一段重述是否安全，问一句：**「如果面试官追问细节，用户能不能原样讲出来？」**

- 能 → 可以写
- 不能 → 这句话现在还不该出现在简历上，先让用户补事实

这条比任何规则都实用，遇到拿不准的改写就用它自检。
