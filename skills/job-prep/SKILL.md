# 面试准备

面试准备的价值不在题目数量，在**每道题都能指向一个具体的证据**。

一份和 JD、简历都对不上的通用题库，用户背了也用不上。

## 0. 前置检查

1. `get_app_status`
2. 确认是哪场面试：`list_interviews`（`upcoming: true`）或用户点名的那条投递

## 1. 取数

`get_interview_context`（传 `applicationId`）一次取够：

- JD 全文与关键词
- 简历正文
- 已有面试轮次
- `existingQuestions`：已经出过的题（**不要重复出**）

## 2. 步骤

### 2.1 出题

围绕三类证据出题，每类都要有：

| 类别 | 来源 | 例子 |
| --- | --- | --- |
| `tech` | JD 的 `blocking`/`important` 技能 | 「你们 JD 里 React 出现 4 次，说说你做过的最难的性能问题」 |
| `project` | 简历里的具体项目 | 「数据看板服务 200 人，那并发峰值是多少、怎么扛的」 |
| `behavior` / `risk` | 简历里的跳跃点、空窗、缺口 | 「你没做过 GraphQL，这个岗位要用，你打算怎么补」 |

**一题一证据**：每道题的 `linkedItem` 必须写清它对应 JD 的哪条要求或简历的哪一条目。
写不出来源的题不要出。

默认出 **15 道**（用户另有要求按用户说的）。`save_question` 逐题落库，带 `provenance`。

### 2.2 练与评分

1. 让用户先说答案，**不要先给参考答案**（先给答案就变成背诵了）
2. 按三维各 1–5 分：
   - `content`：信息量与准确性（有没有具体数字、有没有说清取舍）
   - `structure`：结构（STAR / 总分总，听众能不能跟上）
   - `delivery`：表达（有没有跑题、有没有超时）
3. 每一分都要有锚点：**哪一句话扣的分**。只给数字的评分没有价值。
4. `score_answer` 落库：`myAnswer` + `score` + `improvement`

### 2.3 面试后复盘

1. 问三个问题：问了什么、哪里答崩了、下次怎么答
2. `update_interview`：`feedback`（复盘原文）、`selfRating`、`result`
3. 挂了也要落库——「哪类问题反复挂」是后续最重要的信号

### 2.4 收尾

准备完成 → `update_interview` 把 `prepStatus` 设为 `done`。

## 3. 产出契约

- 15 道题全部落库（`origin: "generated"` + `provenance`），不允许只在对话里列出来。
- 每道题都有 `linkedItem`。
- 评分必须有锚点句子。
- 结束时 `prepStatus = "done"`。

## 4. 确认点

- 用户说「直接给我答案」时：可以给，但要先说明「背下来的答案在追问下会露」。
- 复盘时用户情绪低落：先接住，再复盘。不要上来就列三条改进点。

## 5. 禁止

- 禁止出与该岗位无关的通用面试题（「请自我介绍」不算，它没有信息量）。
- 禁止编造用户没做过的项目细节来「丰富答案」。
- 禁止只给分数不给锚点。
- 禁止把面试结果直接改成 `rejected` 而不问用户——面试结果由用户告知，不能猜。
