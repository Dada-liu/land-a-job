# 浏览器兜底：WorkBuddy 与 Kimi

本地服务抓不到 JD 时，浏览器采集在 **Agent 侧**发生，不在应用里。应用不会启动浏览器、不会调用模型，
也不会拿到你的登录凭证；浏览器读到的正文由 Agent 通过 `import_jd` 写回本地库。

## 通用原则（两家都适用）

- **先征求同意**：浏览器会复用你当前浏览器里的登录态。动手前问一句「可以用浏览器读这个页面吗」。
- **只开用户给的那条链接**，不访问 JD 正文里出现的链接，不做点击提交、不填表、不改页面内容。
- **不为抓 JD 绕验证码或登录墙**：遇到就停下来，请用户自己登录后再继续；这属于站点明确设的门槛。
- **只读取可见的岗位正文**：岗位标题、公司、城市、薪资、职位描述、任职要求、团队介绍都要；导航、推荐岗位、页脚广告不要。
- 有些站点职责区是滚动懒加载的，滚动到底再读一次，避免只拿到前半段。
- 读完关掉临时标签页；不要留下登录态被意外使用的窗口。
- 输出给 `import_jd` 的是**原文**，不摘要、不改写、不翻译、不补全缺失信息。

## WorkBuddy

1. 加载 `workbuddy-browser-use` Skill。使用扩展控制本机浏览器时，需要先在「设置 → Agent → Browser control」开启浏览器控制，并安装 Chrome / Edge / QQ 浏览器扩展；用内置浏览器（IAB）则不需要扩展。
2. 打开一个新标签页并跳转到用户给的招聘链接，等待正文渲染完成（不要只等标题出现）。
3. 读取当前页的可见 DOM 文本（可见 DOM / 页面文本能力），必要时滚动后补读懒加载段落。
4. 从结果里圈出岗位正文区域，去掉导航与推荐位，保留完整职责与要求条目。
5. 关闭临时标签页。

若返回的是登录页、验证码页或一串不相关岗位标题，视为**没取到**，不要拿它当 JD。

## Kimi

Kimi 的浏览器能力叫「**Kimi 浏览器扩展**」（原名 Kimi WebBridge），支持 Chrome 与 Edge。
它通过本地桥接服务 + CDP 在你当前浏览器里完成跳转、读取与内容提取，沿用已有登录态，页面内容不离开设备。
本机若装了 `kimi-webbridge` Skill，直接按它的说明操作即可；下面是为了读 JD 的最小步骤。

1. 确认扩展已连接（本地桥接默认在 `http://127.0.0.1:10086/command`）。在 **Kimi Work** 中从插件市场安装、输入框用 `/` 选中「Kimi 浏览器扩展」；在 **Kimi Code** 中到设置里启用。
2. 打开链接：`navigate` 传用户给的 URL 与 `newTab: true`；如果用户已经开着这个岗位页，用 `find_tab` 传 `active: true` 借用当前标签页。
3. 读正文：先用 `snapshot` 看无障碍树确认这是岗位详情页（有职责与任职要求），再用 `evaluate` 读取岗位正文区域的文本。不要让扩展去点「投递」或填写任何表单。
4. 自检：正文含公司、岗位名、城市、薪资、职责、要求；不足 80 字、只有标题、或出现登录页/验证码就视为没取到，改用人工粘贴。
5. 收尾：`close_tab` 关掉临时标签页，或 `close_session` 关掉本次会话；不要留下登录态被意外使用的窗口。

扩展也支持把重复流程「录成技能」或「把会话存为技能」，但那是网页工作流技能，不是本仓库的 `jd-collect`；两者别混用。

> 只在自己被授权访问、且站点条款允许的页面上使用；涉及账号权限或表单提交时先核对目标。

## 其它 Agent 与最终降级

任何具备「打开页面 + 读正文」能力的 Agent 都可以走同一条链路：读回原文 → `import_jd` 落库 → `get_job` 核对。
如果当前环境完全没有浏览器能力，或页面始终读不到正文，就请用户复制完整 JD 发过来，再用 `import_jd` 写入。
**不要用岗位标题、搜索摘要或记忆拼一份 JD**，也不要把失败说成「岗位不匹配」。

## 落库后的验收

- `import_jd` 返回里 `source` 标为 Agent 浏览器，`job` 带正文长度与关键词。
- `get_job` 能读到完整正文；Web 岗位详情刷新后能看到采集来源与抽取出的年限/学历/城市/薪资。
- 若 `warnings` 里提示域名未验证或内容像列表页，回到页面再核对一次，不要静默通过。
